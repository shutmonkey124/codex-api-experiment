# API research and product decision

Evaluated **23 October 2026** from the actual [public-apis/public-apis directory](https://github.com/public-apis/public-apis), retrieved from `raw.githubusercontent.com`. Priorities: everyday usefulness, free access, no credentials, maintained documentation, geographic reach, a complete useful workflow, and actual connectivity.

## Why Elsewhere

A hotel price, a flight fare, and a meal estimate each look manageable. The entire trip requires multiplying nights, days, and people, converting currencies, then leaving room for surprises. That spreadsheet problem is real even for a short weekend.

Elsewhere focuses on the decision **before booking**: enter local prices, see the complete home-currency total, and compare changes before applying them. Booked versus estimated costs give the buffer a precise meaning. “One more night” produces a concrete budget impact instead of another chart. Browser-local storage and portable files remove signup friction without claiming live collaborative sync.

Currency API won on practical usefulness, broad coverage, no credentials, maintained current documentation, documented redundancy, and confirmed access in the actual environment. No hotel quotes or exchange rates are fabricated.

Current tables were dated **2026-10-23**, with **339** entries including crypto/metals. Observed rates: `1 USD = 0.89177251 EUR`; `1 EUR = 1.12136222 USD`. The app supports 42 curated fiat currencies. CORS was `Access-Control-Allow-Origin: *`.

The live table was also verified through the actual backend and Chromium. A direct browser request initially failed because Chromium did not trust the workspace's outbound proxy certificate. Using the Node backend's existing trusted proxy configuration resolved it, preserving TLS checks.

The documented Cloudflare fallback is implemented and tested with synthetic failures. Its host is blocked here; live fallback availability is not claimed. The primary works. Run `npm run verify:api` to repeat current/historical checks with real network responses.
